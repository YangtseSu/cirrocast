**Language, messages, layout (section 3) — all fixed.**

`--lang en*` resolves to `en-US` without a warning; `LanguageRequest::parse` normalises POSIX
spellings (`zh_CN.UTF-8` → `zh-CN`); a Fluent pattern error returns the raw key; the missing-key
record is per key, not per run; the `-v` missing-key dump runs after the render; the 16
`keys::DIRECTIONS` entries are in `RENDERER_KEYS`; `--lat/--lon` report the command-line source;
the help epilogue spells `LOCATION CIRROCAST_LOCATION`; the unknown-location message no longer
promises a candidate list (`location search` resolves one place), and the unknown-station message
points at coordinates (`cirrocast -p metar @lat,lon`), which do resolve the nearest station;
`error_message` bounds a JSON `reason`/`message` like the raw-body fallback.

**Providers (section 4) and model/units (section 5) — all fixed.**

- 4.1 QWeather 515 → 56; 4.2 the host must be `https://<account>.re.qweatherapi.com` in both the
  config validator and the provider (legacy/plain-http hosts are rejected); 4.3 WWO's
  `data.error` envelope is an `Error::Upstream`; 4.4 Pirate Weather routes humidity/cloud cover/
  probability through the `-999` sentinel filter.
- 5.1 a non-finite reading is refused at **one** choke point: `Provider::fetch` is now a provided
  method that validates the report; backends implement the new `fetch_report`. This is a public
  trait change — deliberate, and the only way no backend can forget the guard.
- 5.2 `round_speed`/`round_two` deleted; METAR stores exact conversions.
- 5.3 `DayForecast::part(kind)` is the accessor every renderer uses (json now indexes by kind), and
  deserialisation rejects a `parts` array whose `kind` fields do not match `[Morning, Noon,
  Evening, Night]` (`parts_in_order`).
- 5.4 `round_half_away_from_zero` nudges only a value within half an ulp *below* a tie, so
  `fmt_int(4_194_303.0) == "4194303"` and `fmt_small` takes the same branch for a negative reading
  as for its positive twin.
- 5.5 `UnitSystem::resolve` treats an empty/whitespace override as absent, like the config layer.
- 5.6 the module doc now says the cache stores raw upstream bodies, not `Report`.
- 5.7 the dead `#[serde(default)]`s on `Option` fields are gone.
- 5.8 added: the signed-temperature/négative-`fmt_small` fixture rows, the `hpa_to_inhg`
  reciprocal doctest, the 17 kt / 10 SM exact-conversion pins, and `tests/model_report.rs`
  (shuffled parts rejected, hostile scalar types rejected, an undescribed code loads as unknown).

## Issues recorded during the unattended run

- **`api.open-meteo.com` is unreachable from this machine**, including through the local proxy
  (geocoding answers, the forecast host times out after three attempts). The default live smoke is
  therefore still outstanding for that endpoint; SMHI and METAR cover the provider/render paths
  end to end. The review's section 12 note stands.
- The QWeather host rule is strict (`https://<account>.re.qweatherapi.com`): a configuration that
  still names a legacy shared host or `http://` now fails validation on every run. That is the
  intended encoding of the documented "Invalid Host" constraint, but it is a behaviour change for
  anyone who had such a host configured.
- `config show` now fails (exit 4) when a `CIRROCAST_*` override is invalid, where it previously
  ignored the environment entirely. Failing loudly matches `config get`'s value; a caller that wants
  the file alone can read `config.toml`.
- `write_default` (used by `config init` and by `config edit` when the file is absent) writes
  canonical TOML without comments when a system document is being shadowed; the commented template
  is kept whenever no other document is in effect.
- `parse_override` trims: an override of `" "` is now "absent" rather than a usage error.
- The `Provider` trait change (`fetch` provided, backends implement `fetch_report`) is a breaking
  API change for any out-of-tree implementor; it is recorded here because the review asked for a
  guard that no provider can skip.
- `docs/plans/14-v1-acceptance.md` still quotes the old location/station error texts as historical
  acceptance evidence; progress logs are not rewritten, so the quote stays as it was.
- Windows and macOS were not exercised (Linux only), as in the review.
