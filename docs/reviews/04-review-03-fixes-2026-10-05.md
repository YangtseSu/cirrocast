## Deviations from the review's prescribed fixes

1. **§3.10 — redirects are refused only for requests that carry a header.** The review's
   `max_redirects(0)` premise ("every upstream in the registry answers its final URL directly") is
   false: the public FPAS server answers `301 Location: /cap/alerts/…` for every
   `GET /alert/<uuid>`, so the blanket refusal broke the FPAS source (and FPAS runs in the `auto`
   alert chain). Live evidence before the fix: `--alerts-from fpas` → exit 3 with
   `provider alerts.kde.org answered HTTP 301:`; after: exit 0 with the CAP documents resolved.
   `UreqTransport` now builds two agents: a header-free request follows at most five hops, a request
   with any header follows none — the credential case the finding was about (the QWeather key and
   the MeteoAlarm token cannot survive a hop). Residual, deliberate: a header-free request may
   follow a cross-host `3xx` (the pre-existing `ureq` behaviour); no credential can travel. Routing
   the host model of §3.15 over redirects is left as a follow-up rather than guessed at here.
2. **§3.8 — the contract was amended, not `covered_days`.** `DayForecast` is four day parts by
   contract, so carrying a partial local today would invent values for the empty parts. The contract
   (and `Report`'s doc) now say `days[0]` is the first location-local date whose four parts all have
   a sample — today whenever the backend's series covers it, which is what the two daily-based
   backends already did.
3. **§3.11 — the credit keeps its licence id and gains the link.** The shipped line is
   `Data: Open-Meteo.com (CC BY 4.0) — https://open-meteo.com/` (the `Data:` label is localized by
   the catalog), and the binding clause now names that exact rendered text. The clause's quoted
   literal would have printed `Data: Weather data by Open-Meteo.com (…)` — the label already says
   "data", and dropping `(CC BY 4.0)` would weaken the credit the licence asks for. Each registry
   row is pinned by a test; `docs/providers.md` follows.
4. **§3.4 — the `VisualCrossing` variant stays, the validator refuses it.** Step 23 wires the
   provider, so the model keeps the variant; `check_alert_sources` rejects it with `Error::Config`
   naming `alerts.sources`, and `--alerts-from` parses and refuses every id in the pre-flight,
   before any location resolution and therefore before any request.
5. **§4.1 #6 was widened beyond its wording.** A `-999` sentinel in Pirate Weather's humidity or
   cloud cover could only null *that field* if the model allowed it, so `Current.humidity_pct` and
   `Current.cloud_cover_pct` became `Option<u8>` (SMHI's in-band `9999` benefits too). Four JSON
   fields are now nullable; `docs/schema.md` records that widening to nullable is additive within
   `schema_version` 2.
6. **§4.4 #46 — fold down, never drop.** An explicit `--color always` under a `TERM` that
   advertises no colour now emits the sixteen ANSI colours (never 256, never nothing); `--format
   dumb` stays monochrome by contract and explains that under `-v`.
7. **§4.2 #24 — `[locations]` still has no `config set` row.** `KEY_TABLE` is a fixed list of dotted
   names and `[locations]` keys are free-form, so a dynamic row is a config-set model change, not a
   one-line fix. `config set location.default` now validates only the key it sets, which was the
   finding.
8. **§4.4 #51 — the `sun`/`uv` preset literals are deferred.** Localizing them needs a new template
   token, i.e. a change to the wttr.in-compatible token vocabulary that belongs to the B01 compat
   step; the `moon` `at` literal and the air-quality credit line moved to the catalogs with
   byte-identical en-US output.

## Refuted

* **§4.7 `deny.toml` getrandom justification.** The recorded reason is correct: `getrandom 0.2.17`
  is reached through `ring` (runtime) and `0.4.3` through `tempfile` (dev-only), and cargo-deny
  filters dev-only versions by default (`multiple-versions-include-dev = false`), so the bans check
  sees one version. No edit; `cargo deny check` passes.
* **§3.9's second option is not an alternative.** Disabling `ureq`'s decoders and refusing a
  non-identity `Content-Encoding` are both in place; the doc sentence now describes what is
  enforced.
* **The review's `MAX_BODY_BYTES` bound is now true end to end**: with the decoders off, the body
  read is exactly the wire bytes, and a non-identity encoding is a typed `Error::Upstream`.

## Issues recorded during the run

* The review's `MAX_BODY_BYTES` claim was checked against `ureq` 3.4.2's own source again after the
  fix: `LimitReader` sits inside the content decoder, which is why the decoders had to go.
* The §3.10 fix means a `CIRROCAST_FORBID_NETWORK=1` run can still reach a redirect target that is
  not the initial URL; no test relies on that, and the credential rule is unaffected.
* `--alerts-from auto` stays rejected by design (`auto` is the coverage selector for
  `[alerts] sources`); the contract, `docs/schema.md` and `--help` now say so.
* The review's §4.1 #11 (short SMHI series) is reported as a `-v` note rather than a warning by
  default, because `--format json` scripts would otherwise see stderr noise on every run.
