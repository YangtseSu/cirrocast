## Deviations from the review's prescribed fixes

1. **§3.1 — the contract was amended; no code moved.** `src/template.rs` is the shared engine behind
   `one-line`, the `full`/`minimal` presets, `status` and the B01 compat surface; it formats through
   `model::units` and holds the renderers' own `RenderContext`, so it already *is* render surface —
   moving it under `src/render/` would churn every caller for a path change. What was actually
   wrong was the wording: "the render layer is the only place that converts units" did not name it.
   The binding text (`docs/plans/README.md`, the canonical-data-model bullet and the rendering
   contract), `AGENTS.md` rule 5 and `docs/architecture.md` now say **render surface = `src/render/`
   plus the shared template engine `src/template.rs`**, and `scripts/check-render-imports.py` holds
   `src/template.rs` to the same no-`http`/`provider`/`cache` rule (21 files, gate green).
   **The review's cache premise does not hold**: the weather key is
   `weather/<provider>-<lat.2dp>-<lon.2dp>-<days>-<local-date>.json` and carries no unit, and the
   template conversion runs after the fetch and its cache write — there is nothing for the cache to
   know about a unit system.
2. **§3.2–3.4 — the fix was widened where the same defect class was present.** The NWS icon/text
   tables (§4.4's own subject) collapsed `haze`/`smoke`/`dust` into `Fog` too, and World Weather
   Online had no arm at all for eleven codes of its published feed (125–161, previously `Unknown`),
   so both were corrected in the same pass; NWS also gained the five published
   `rain_snow`/`*_sleet`/`*_fzra` icons and the `blowing dust`/`blowing snow` text rows its vendor
   list carries. The review's "split according to the WMO 4677 standard" cannot be literal
   everywhere: the standard's duststorm codes (9, 30–35) are not in this crate's table and smog has
   no WMO code at all, so the storm forms and smog take the nearest described family with a comment
   saying so — the convention the OpenWeatherMap volcanic-ash/tornado arms already use.
3. **§4.1 — documented, not split.** A comma is meaningful *inside* a location spec: `@39.9,116.4`
   is one coordinate pair and `Beijing, China` is one name. Splitting the environment value on
   commas would break the coordinate spelling, so the environment tier stays single-spec (exactly
   the review's first option): the `--help` epilogue, its `man` page, `docs/configuration.md`,
   `docs/location.md` and the contract now say that `CIRROCAST_LOCATION` names one location and that
   a multi-location run belongs on the command line. The help/man snapshots were regenerated.
4. **§4.2 — the accessor went, the messages stayed.** `format-temp-c`/`format-temp-f` are part of
   the documented reserved-key family in `RENDERER_KEYS` (the wind, pressure, distance and
   precipitation spellings are equally uncalled and equally listed), so deleting them would have
   singled out temperature for no reason; what was misleading was the public wrapper that looked
   like the conversion path. It is gone, and step 09's deliverable list and progress log record the
   removal.
5. **§4.4 — pinning the tables is what found the bug.** The new NWS tests use the vendor's
   published `/icons` list as an independent expectation rather than echoing `ICON_CODES`; the
   collapse (and the five missing icons) surfaced from that comparison, so the test and the fix
   landed together.

## Refuted

* **§4.3 "SMHI has zero test coverage."** `tests/provider_smhi.rs` drives the recorded SNOW1gv1
  response through the shared harness — the request shape (lon before lat), day-part aggregation,
  the `9999` sentinel, the out-of-coverage error, a provisional-zone refusal and the cache — and the
  review's own §5 table shows the suite exists. What was genuinely missing was an exhaustive
  *mapping* pin; the module now carries a table test over all 27 published symbols plus hostile
  values (`0`, `28`, `99`, `−1`, `NAN`, `INFINITY` stay undescribed; `4.6` rounds to `5`).
* **§4.4 "NWS condition mapping functions lack test coverage."** `tests/provider_nws.rs` covers the
  recorded payloads, the recorded conditions and the unknown-text fallback; the gap was the tables
  *as tables*, now pinned (35 icon entries, the text table's longest-first ordering, the
  most-severe-segment reduction, the `-v` note), which is how the obscuration collapse was found.
* **§4.5 "multiple providers lack fixture-based tests."** All four have recorded fixtures and
  suites: `tests/provider_owm.rs` (`tests/fixtures/owm/`), `tests/provider_weatherapi.rs`,
  `tests/provider_pirateweather.rs`, and `tests/provider_visualcrossing.rs` (a hand-authored
  timeline, documented as such in its header and in `tests/fixtures/visualcrossing/`). The review
  inspected the in-crate `#[cfg(test)]` modules only; the repository's policy is that provider
  decoding is tested against recorded fixtures in `tests/`.
* **§4.6 "`--severity` is silently ignored without `--alerts`."** `alert_request` reads
  `query.severity` as the threshold whenever an alert fetch happens, and `[alerts] enabled` defaults
  to `true`, so `--severity severe -f plain` *does* shape that run's fetch; the review's two probes
  compared runs in which no qualifying alert was in force, hence the identical output. The
  `--aqi-index` analogue does not transfer either — the air panel is fetched only on request, alerts
  are fetched by default — and the one combination that really is meaningless (`--no-alerts` with
  `--severity`) is already a usage error (exit 2, the `severity_cannot_be_combined_with_no_alerts`
  unit test in `src/cli.rs`). Since the review found the flag unobservable, the gap in *coverage* it
  exposed is closed: `tests/alerts.rs` now pins that a Minor alert survives the Minor threshold and
  not the Severe one (`the_severity_threshold_keeps_the_alerts_at_or_above_it`).
* **§5.3 "`I18n::load` uses `std::env::var`, so tests must mutate the environment."** `I18n::load`
  takes `environment: impl Fn(&str) -> Option<String>`; the CLI passes `std::env::var`, the unit
  tests pass a map, and no test touches the process environment — the seam is the documented design
  of step 09.
* **§5.11, §5.12, §5.13, §5.14, §5.15 — no defect.** The `Default | Alias` arm of
  `resolve_candidates` is a programmer backstop that both callers make unreachable by expanding
  aliases first; the coordinate-name comparison shares the one `coordinate_name` helper in the same
  module, so it cannot drift; `Error::Other`'s chain text is `-v` output, not an error message;
  `ExitCode::from(u8)` cannot truncate the 0–6 table; and the max-exit-code policy is stated in
  `lib.rs` and the contract.
* **§5.1, §5.2, §5.4, §5.5, §5.9, §5.10 — no change.** The bool count is annotated with the reason
  it is a set of independent switches; the validator ordering only picks which correct usage message
  a user sees; the language chain and the `zh`-family substitution are documented design and are
  printed under `-v`; and splitting `art_table.rs`/`json.rs` by line count would move code without
  changing behaviour — there is no finding behind it, only a size.
